# i18n 4 nyelv — Next.js 14 App Router megoldások (de/en/fr/it)

- **Dátum:** 2026-08-26
- **Szerző:** researcher (Research Agent 1)
- **Állapot:** draft → ADR-javaslat
- **Kapcsolódik:** `frontend/package.json` (Next 14.2.35), `frontend/src/app/layout.tsx` (`lang='en'` hardcode), `frontend/src/app/page.tsx` (német UI szövegek: Steuerfuss/Lärm/ÖV/Planung), `METHODOLOGY.md` 5. fejezet, `docs/decisions/ADR-001-*`
- **Téma:** 4 nyelvű (de/en/fr/it — CH hivatalos + EN) i18n App Routerben: routing, detektálás, SEO, karbantarthatóság

---

## 1. Kontextus & követelmény

Swiss P Map FE: **Next.js 14.2.35 App Router** + Tailwind + Three.js 0.160. Jelenleg nincs i18n: `layout.tsx` fix `lang="en"`, `page.tsx`/`SearchPanel`/`Map3D` német szövegekkel; nincs `[locale]` szegmens, nincs middleware. Követelmény: **4 locale** (`de` default, `en`, `fr`, `it`), URL-alapú routing (`/de/...`), `Accept-Language` detektálás csak prefix nélküli úton, cookie megjegyzés, **SEO**: `hreflang` + `canonical` + `x-default`, `sitemap.ts` alternates, `<html lang>` dinamikus.

Next.js App Routerben **nincs beépített i18n routing** (a Pages Router `next.config i18n` megszűnt). A hivatalos App Router guide (2026-06-10) manuális middleware + `[locale]` szegmenst ír elő [nextjs.org](https://nextjs.org/docs/app/guides/internationalization).

## 2. Vizsgált opciók (2024–2026 élő állapot)

### A — `next-intl` 3.x / 4.x (App Router-first, full-stack)

- **Mi:** Fordítás + `Intl` formázás + middleware routing + navigációs API-k (`Link`, `useRouter`, `usePathname`, `redirect`) egy csomagban. 3.0 (2023-11) volt az első App Router-first kiadás (RSC `useTranslations`, async `getTranslations`, `NextIntlClientProvider` Server Componentben) [next-intl.dev/blog/next-intl-3-0](https://next-intl.dev/blog/next-intl-3-0). 4.x (2025–2026) Next 15/16-ra frissítve, de `peer: ^14 || ^15 || ^16` — 14-gyel kompatibilis.
- **Verzió & health (2026-08):** `4.13.7` (2026-08-17), `4.13.6` (2026-08-10) a CHANGELOG-ban [github.com/amannn/next-intl/blob/HEAD/CHANGELOG.md](https://github.com/amannn/next-intl/blob/HEAD/CHANGELOG.md); `v3.26.5...v4.8.3` diff mutatja a 4.0 `feat: next-intl@4` migrációt [github.com/amannn/next-intl/compare/v3.26.5...v4.8.3](https://github.com/amannn/next-intl/compare/v3.26.5...v4.8.3); npm `next-intl` `4.5M heti letöltés`, támogatott `next ^12||^13||^14||^15||^16` [registry.npmjs.org/next-intl](https://registry.npmjs.org/next-intl) / [npmjs.com/package/next-intl](https://www.npmjs.com/package/next-intl); Next 14 támogatás PR #593 óta (2023-11-02) [github.com/amannn/next-intl/pull/593](https://github.com/amannn/next-intl/pull/593).
- **Routing:** `createMiddleware` + `defineRouting` (next-intl 3.22+/4.x) `localePrefix: 'always'` → `/de`, `/en`, `/fr`, `/it`; `localeDetection` header → cookie → default; `matcher` a prefix nélküli utakra.
- **SEO:** `generateMetadata` → `alternates.languages` + `canonical`, `app/sitemap.ts` `alternates.languages` per entry — Next.js automatikusan `<link hreflang>`-et generál. Minta 2026-os deep-dive cikkben részletezve [nextfuture.io.vn](https://nextfuture.io.vn/blog/technical-seo-nextjs-app-router-structured-data-hreflang-isr-sitemaps).
- **Pro:** type-safe `t('key')`, ICU plural/select, `Intl.DateTimeFormat/NumberFormat/RelativeTimeFormat` támogatás, RSC + static rendering (`unstable_setRequestLocale` / `setRequestLocale` — 3.0 óta), `next-intl/plugin` SWC plugin.
- **Kontra:** egy extra build plugin + `i18n.ts`/`request.ts` konfiguráció; `localePrefix: always` esetén minden belső `Link`et az i18n-es API-ra kell cserélni.

### B — `next-i18n-router` + `react-i18next` / `react-intl`

- **Mi:** Kizárólag routing-middleware (i18nexus), fordítást **nem** ad — bármely i18n lib mellé tehető. Leírás: *“With the release of the App Router, internationalized routing has been removed … This library adds back internationalized routing in addition to locale detection and optional cookie usage”* [npmjs.com/package/next-i18n-router](https://www.npmjs.com/package/next-i18n-router) / [github.com/i18nexus/next-i18n-router](https://github.com/i18nexus/next-i18n-router).
- **Működés:** `i18nConfig.js` (`locales`, `defaultLocale`, `prefixDefault`, `noPrefix`), `middleware.js`-ben `i18nRouter(request, i18nConfig)`, `app/[locale]/` szegmens, `useCurrentLocale()` Client hook, Serverben `params.locale`. Detektálás: `@formatjs/intl-localematcher` az `Accept-Language` headerből (Next.js docs által ajánlott stratégia), opcionális `localeDetector: false` + cookie.
- **Pro:** pici, fókuszált, `react-i18next` ismerős ha már használják; külön választható fordító.
- **Kontra:** két felelősség (router + fordító) külön verziózva; nincs beépített `Link`/`redirect` lokalizáció, nincs ICU/formatter out-of-box; SEO (`hreflang`, `sitemap alternates`) teljesen kézi; `react-intl` RSC-ben extra konfigot igényel (dokumentált tutorial szükséges).

### C — Custom `[locale]` routing (kézi dictionary)

- **Mi:** `app/[locale]/layout.tsx` dinamikus szegmens + saját `middleware.ts` (accept-language parse, cookie, redirect) + `lib/dictionaries/{de,en,fr,it}.json` + `getDictionary(locale)` helper + `generateStaticParams() => locales.map(l=>({locale:l}))`. Bemutatva: Next.js App Router guide [nextjs.org/docs/app/guides/internationalization](https://nextjs.org/docs/app/guides/internationalization), SitePoint Next 14 i18n cikk [sitepoint.com/next-js-internationalization](https://www.sitepoint.com/next-js-internationalization/), Dev.to Next 14 App Router kézi i18n [dev.to/fabrikapp/implementing-internationalization-i18n-in-nextjs-14-using-app-router-3mic](https://dev.to/fabrikapp/implementing-internationalization-i18n-in-nextjs-14-using-app-router-3mic), blog példa hreflang/sitemap kézzel [abdelrahmanmostafa.com/blog/multi-language-site-in-nextjs](https://abdelrahmanmostafa.com/blog/multi-language-site-in-nextjs).
- **Pro:** 0 külső függőség, teljes kontroll, bundle kicsi.
- **Kontra:** minden i18n feature-t magad írsz: pluralizáció, dátum/szám formázás (`Intl` kézzel), `Link` lokalizálás, `hreflang`/`canonical`/`sitemap` generálás, redirect-loop és cache-key buktatók (pl. header-alapú render kerülendő — URL legyen a cache kulcs). Új nyelv = új JSON + minden `generateMetadata` frissítése.

## 4. Javaslat — **A: `next-intl` (3.26.x stabil / 4.13.x legfrissebb)**

**Swiss P Map-hez ez illik**, mert:

1. **App Router natív:** A projekt `next 14.2.35` — `next-intl` 3.0 óta App Router-first, 4.x is `^14`-et peer-eli; RSC `getTranslations` + `setRequestLocale` statikus render megmarad.
2. **4 nyelv + IC:** `de` (default, CH-de), `en`, `fr`, `it` — ICU `plural`/`select` (pl. “1 Baugesuch / 2 Baugesuche”) és `Intl` formázás (Steuerfuss `%`, dB, dátum) dobozból.
3. **SEO determiniszikus:** `localePrefix: 'always'` → minden URL prefixelt (`/de/8001`, `/fr/8001`) → CDN cache kulcs = URL, nincs header-vary probléma; `generateMetadata` → `alternates.languages` + `x-default` + `canonical`, `sitemap.ts` `alternates` per locale (Next.js generálja a `<xhtml:link hreflang>` taget). Ez a Next.js SEO deep-dive ajánlása is.
4. **Detektálás:** `middleware` csak prefix nélküli `/` és legacy `/place/8001` esetén: `Accept-Language` → `NextIntlMiddleware` → cookie (`NEXT_LOCALE`) → `de` fallback; prefixelt URL mindig nyer (nincs redirect-loop).
5. **DX & karbantartás:** Egy forrásnyelv (`messages/de.json` teljes, többi fallback), `i18n/request.ts` server config, `navigation.ts` `createLocalizedPathnamesNavigation` ha később `/ueber-uns` ↔ `/about` lokalizált path kell — de MVP-ben elég az azonos pathname.

**Konkrét beállítás (kód nélkül, terv):**

- `routing: { locales: ['de','en','fr','it'], defaultLocale: 'de', localePrefix: 'always', localeDetection: true }` + `middleware.ts` matcher `['/', '/(de|en|fr|it)/:path*', '/((?!api|_next|_vercel|.*\\..*).*)']`
- `app/[locale]/layout.tsx` (`params.locale` validál + `setRequestLocale`, `<html lang={locale}>`), `app/[locale]/page.tsx` (jelenlegi `page.tsx` átmozgatva), `messages/{de,en,fr,it}.json`
- `generateMetadata` + `sitemap.ts` a `hreflang`/`x-default` központi helperrel; `next.config.mjs`-be `createNextIntlPlugin('./i18n/request.ts')`
- Migráció: `3.26.5` konzervatív (bőven tesztelt Next 14-en) vagy `4.13.x` (aktuális, hosszabb támogatás) — mindkettő Next 14-gyel megy; 4.x esetén `next-intl/plugin` új `routing` API-t használd (a `middleware` import `next-intl/middleware` → `next-intl/server` deprecált 3.0 óta).

**Elvetve:**
- **B:** Akkor értelmes, ha a csapat már `react-i18next` ökoszisztémában van és ragaszkodik hozzá; nálunk zöldmező + nincs meglévő fordító → extra glue indokolatlan.
- **C:** Csak extrém bundle-méret kényszernél vagy multi-tenant custom path logikánál éri meg; 4 nyelv + SEO + formázás mellett a kézi költség hamar meghaladja a `next-intl` tanulási költségét.
